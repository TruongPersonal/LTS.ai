## 1. Problem Context

#### Neo — Tình huống thực tế

Bạn xây một trang sản phẩm: mỗi sản phẩm có nút "Thêm vào giỏ" và một ô nhập số lượng. Khi người dùng bấm nút, số lượng phải tăng lên, tổng tiền phải thay đổi, và icon giỏ hàng phải hiển thị số lượng mới.

function ProductCard() { let quantity = 1;

function handleIncrease() { quantity = quantity + 1; // quantity giờ là 2, nhưng UI không thay đổi }

return ( <div> <p>Số lượng: {quantity}</p> <button onClick={handleIncrease}>+</button> </div> ); }

Bạn bấm nút, console log thấy quantity tăng, nhưng màn hình vẫn hiển thị "Số lượng: 1".

#### Manual — Cách dùng biến thường

Lập trình viên mới học React thường nghĩ: "Tôi khai báo một biến, thay đổi nó, React tự cập nhật UI." Điều này có vẻ hiển nhiên — JavaScript vẫn làm thế mà: let x = 1; x = 2; console.log(x); // 2.

Nhưng React không hoạt động như vậy. Component function chạy một lần để **render** ra JSX. Khi bạn thay đổi biến cục bộ bên trong function, component không tự động chạy lại.

#### Điểm gãy — Tại sao biến thường không đủ

Nếu React dùng biến thường để quản lý dữ liệu thay đổi, bạn gặp 3 vấn đề:

1. **UI không đồng bộ với dữ liệu** — biến đã đổi nhưng component không re-render, màn hình vẫn hiển thị giá trị cũ
2. **Không có cơ chế báo hiệu "dữ liệu đã thay đổi"** — React không biết khi nào cần cập nhật DOM
3. **State bị mất sau mỗi lần render** — mỗi lần component chạy lại, biến cục bộ được khai báo lại từ đầu
Dùng let hay const đều không giải quyết được: vấn đề không nằm ở cách khai báo mà ở việc thiếu cơ chế thông báo cho React rằng "dữ liệu đã đổi, cần render lại". **Cầu nối — Cần một cơ chế có nhớ + báo hiệu**

React giải quyết bằng **state**: một giá trị được React quản lý, có khả năng "nhớ" giá trị giữa các lần render, và khi thay đổi sẽ báo cho React biết để re-render component.

const [quantity, setQuantity] = useState(1);

quantity — giá trị hiện tại, được React nhớ giữa các lần render setQuantity — function để cập nhật, đồng thời báo React "cần re-render"

## <u>3. Weakness — Khi không có state, mọi thứ gãy</u>

### Scenario 1: Đồng hồ đếm ngược

Bạn muốn một đồng hồ đếm từ 60 giây về 0, dùng setInterval :

function Timer() { let seconds = 60;

useEffect(() => { const id = setInterval(() => { seconds = seconds-1; console.log(seconds); // 59, 58, 57... trên console }, 1000); return () => clearInterval(id); }, []);

return <p>⏱ {seconds}s</p>; // Luôn hiển thị 60 }

**Hậu quả:** Màn hình luôn hiển thị 60 dù console log giảm dần. Biến seconds thay đổi trong interval callback, nhưng component không re-render — React không biết rằng dữ liệu đã thay đổi.

### Scenario 2: Giỏ hàng với nhiều sản phẩm

function Cart() { let items = []; let total = 0;

function addItem(product) { items.push(product); total = total + product.price; // items và total đã thay đổi, nhưng UI không cập nhật }

return ( <div> <p>Tổng: {total}đ</p> <p>Số lượng: {items.length}</p> <button onClick={() => addItem({ name: "Áo", price: 200})}>Thêm</button> </div> ); }

**Hậu quả:** Người dùng bấm "Thêm" nhiều lần — UI không đổi, nhưng thực tế items và total đã thay đổi trong bộ nhớ. Khi mua hàng, dữ liệu gửi lên server mới đúng, nhưng người dùng thấy UI sai và không tin tưởng.

### Scenario 3: Form input không thể gõ

Đây là lỗi kinh điển khi mới học React:

function SearchBox() { let keyword = "";

function handleChange(e) { keyword = e.target.value; // keyword thay đổi, nhưng <input> vẫn hiển thị giá trị cũ }

return <input value={keyword} onChange={handleChange} />; }

**Hậu quả:** <input value={keyword}> là **controlled component** — React kiểm soát giá trị hiển thị. Vì keyword là biến thường, component không re-render, input luôn hiển thị chuỗi rỗng. Người dùng gõ nhưng không thấy chữ hiện ra — tưởng máy tính hỏng.

***Cốt lõi của tất cả vấn đề:** React cần một cơ chế để biết "dữ liệu nào thay đổi" và* *"component nào cần re-render". Biến thường không cung cấp cơ chế đó.*

### 4.2 Bên dưới — React nhớ state như thế nào? (P1)

**Dữ liệu lưu ở đâu:** React lưu state trong một cấu trúc dữ liệu nội bộ gắn với từng component instance — thường gọi là **fiber node**. Fiber node nằm trên **JS heap**, không phải DOM tree.

Fiber tree (JS heap) DOM tree (trình duyệt) ┌─────────────────┐ ┌────────────────────┐ │ App fiber │ │ <div id="root"> │ │ ┌─────────────┐ │ │ ┌──────────────┐ │ │ │ Counter │ │ │ │ <div> │ │ │ │ fiber │ │ │ │ <p>Count: │ │ │ │ state: [0] │ │ │ │ 0</p> │ │ │ │ queue: [...]│ │ │ │ <button> │ │ │ └─────────────┘ │ │ │ +1 │ │ └─────────────────┘ │ │ </button> │ │ │ │ </div> │ │ │ └──────────────┘ │ └────────────────────┘

#### Trình duyệt/framework thực thi thế nào:

1. **Mount (lần đầu):** React chạy component function → gặp useState(0) → tạo fiber node, lưu st ate = 0 trong hàng chờ (queue). Render ra JSX, commit DOM.
2. **setState được gọi:** React thêm update vào queue của fiber node. Đánh dấu component cần re- render.
3. **Re-render:** React chạy lại component function. useState đọc giá trị mới nhất từ queue (không dùng initialValue nữa). Hàm trả về JSX mới.
4. **Reconciliation:** React so sánh JSX mới với JSX cũ, tính ra DOM thay đổi tối thiểu.
5. **Commit:** Cập nhật DOM thật.
**Thứ tự operation được đảm bảo không:** Có, trong cùng một lần render, mọi useState trong component đều chạy theo đúng thứ tự khai báo (quy tắc "chỉ gọi hook ở top level").

#### State thay đổi khi nào, ai thấy:

State thay đổi khi setState được gọi (sau event handler, effect, timeout...) Chỉ component chứa state đó (và component con) thấy sự thay đổi qua re-render Component sibling không bị ảnh hưởng trực tiếp

### 4.3 Render lifecycle (P7)

#### Lifecycle của một component có state:

[Mount] → [Render lần 1] → [Commit DOM] → [Idle] ↑ [setState()] → [React đánh dấu dirty] ↓ [Re-render] → [Reconcile] → [Commit DOM] → [Idle]

#### Giải thích:

1. **Trigger phase** — nguyên nhân re-render: State thay đổi ( setState ) Props thay đổi (component cha re-render truyền xuống) Force update (không khuyến khích)
2. **Render phase** — React chạy component function: Gọi function component Thu thập JSX/React elements **Có thể bị gián đoạn** (React 18 concurrent mode)
3. **Reconciliation phase** — so sánh: So sánh element tree mới với cây cũ (diffing) Xác định DOM thay đổi tối thiểu
4. **Commit phase** — cập nhật DOM: Áp dụng thay đổi vào DOM thật

### Bước 4 — State với object/array — immutable update pattern

Shopping Cart cần quản lý danh sách sản phẩm trong giỏ:

function ShoppingCart() { const [items, setItems] = useState([]);

function addItem(product) { // ❌ SAI — mutate trực tiếp items.push(product); setItems(items); // React không thấy thay đổi (cùng reference) }

// ✅ ĐÚNG — tạo mảng mới function addItem(product) {
setItems(prev => [...prev, {...product, quantity: 1}]);
}

function increaseQuantity(productId) { // ✅ ĐÚNG — map ra mảng mới, không mutate item cũ setItems(prev => prev.map(item => item.id === productId ? {...item, quantity: item.quantity + 1} : item ) ); }

function removeItem(productId) { setItems(prev => prev.filter(item => item.id!== productId)); } }

#### Tại sao immutable pattern quan trọng:

React dùng Object.is để so sánh state cũ và mới Nếu cùng reference → React cho rằng state không đổi → bỏ qua re-render Luôn tạo array/object mới (spread, map, filter, slice...)

### useReducer — useState cho logic phức tạp

Khi state có nhiều field hoặc update logic phức tạp, useReducer là bước kế tiếp:

const [state, dispatch] = useReducer(cartReducer, initialState);

function cartReducer(state, action) { switch (action.type) {
case'ADD': return {...state, items: [...state.items, action.product]};
case'REMOVE': return {...state, items: state.items.filter(i => i.id!== action. id)}; case'CLEAR': return {...state, items: []}; default: return state; } }

useReducer giống useState nhưng dùng reducer pattern — thích hợp khi state update logic cần được tách riêng khỏi component.

### React 19: use() hook

React 19 (future) giới thiệu use() hook — cho phép đọc context và promise ngay trong render, thay đổi cách quản lý async state. useState vẫn là cơ bản, nhưng các pattern async sẽ thay đổi.

### Concurrent features và state

React 18 concurrent mode cho phép React "tạm dừng" render để xử lý update quan trọng hơn (ví dụ: giữ nguyên input hiện tại). State trong concurrent mode vẫn hoạt động như mô tả — nhưng thứ tự commit có thể khác nếu có urgent update chen vào.

### Kết luận

State là trái tim của React. Hiểu useState — đặc biệt là immutable update, updater function, batching, và derived state — là nền tảng để học useEffect, useContext, useReducer, và mọi state management phức tạp hơn. Nếu nắm vững "state là snapshot mỗi render" và "không mutate trực tiếp", bạn đã tránh được 80% bug React phổ biến.
