## 1. Problem Context

#### Neo — Tình huống thực tế

Bạn xây một trang tìm kiếm sản phẩm cho cửa hàng online. Trang có:

Một ô input để nhập từ khóa tìm kiếm Một danh sách sản phẩm được lọc theo từ khóa (có hiệu ứng debounce — đợi người dùng gõ xong mới lọc) Khi click vào sản phẩm, thêm vào giỏ hàng Ô input tự động focus khi trang mở Giỏ hàng hiển thị tổng tiền, chỉ tính lại khi giỏ hàng thay đổi

Bạn có 5 nhu cầu khác nhau quản lý dữ liệu và side-effect, và cần chọn đúng công cụ cho từng nhu cầu.

#### Manual — Cách suy nghĩ naïve

Lập trình viên mới học React thường nghĩ: "Tôi cần một biến → useState. Tôi cần chạy code khi component mount → useEffect. Vậy là đủ." Nhưng sau đó gặp hàng loạt vấn đề: effect chạy không đúng lúc, component re-render quá nhiều, function bị tạo lại mỗi lần render gây mất reference, input không focus được vì React kiểm soát DOM.

#### Điểm gãy — Thiếu hiểu biết về hooks dẫn đến 4 class bug

1. **Re-render tràn lan** — không dùng useMemo / useCallback, mỗi lần render tính toán lại toàn bộ, component con nhận props mới (dù giá trị không đổi) → re-render theo.
2. **Stale closure** — effect hoặc callback đọc giá trị cũ của state vì closure bị capture tại thời điểm render trước, không thấy giá trị mới.
3. **Infinite loop** — effect gọi setState, setState trigger re-render, re-render chạy effect lại → lặp vô hạn.
4. **DOM ref không dùng được** — cần focus input, đo kích thước element, nhưng React che DOM — không có document.querySelector trong React world.
#### Cầu nối — Mỗi hook giải quyết một vấn đề cụ thể

React cung cấp **hooks** — một hệ thống function cho phép function component "kết nối" vào React internal state, lifecycle, và DOM ref. Mỗi hook giải quyết đúng một vấn đề:

|Hook|Giải quyết vấn đề|
|---|---|
|useState|Dữ liệu thay đổi theo thời gian, cần trigger re-render|
|useEffect|Side-effect gắn với lifecycle (mount/update/unmount)|
|useRef|Truy cập DOM element trực tiếp, giữ giá trị qua các render mà không gây re-render|
|useMemo|Tính toán đắt, chỉ chạy lại khi dependency thay đổi|
|useCallback|Function ổn định về reference, tránh re-render component con|

**Điều quan trọng:** Thứ tự hook trong linked list phải **giống nhau giữa các lần render**. Nếu lần render đầu có 6 hooks, lần render sau cũng phải đúng 6 hooks theo đúng thứ tự. Đây là lý do **rules of** **hooks** tồn tại — không đặt hook trong if, for, hay function lồng.

### 4.3 Mỗi render có một closure riêng

Khi component re-render (state thay đổi), React chạy lại toàn bộ function component — tạo ra một **render scope mới**. Mỗi hook "nhìn" giá trị state tại thời điểm render đó:

function Counter() { const [count, setCount] = useState(0);

function handleClick() { setCount(count + 1); // count ở đây là giá trị TẠI LÚC RENDER này }

// Khi click lần 1: render lần 1 count=0 → setCount(1) // Khi click lần 2: render lần 2 count=1 → setCount(2) return <button onClick={handleClick}>{count}</button>; }

Hiểu được mỗi render có closure riêng là chìa khóa để debug stale closure và infinite loop.

### 4.4 Rules of Hooks — tại sao bắt buộc?

1. **Chỉ gọi hooks ở top level** — không trong if, for, switch, hay function lồng. Lý do: React dựa vào thứ tự gọi hooks để ghép đúng state giữa các lần render. Nếu lần render đầu gọi hook A rồi hook B, lần render thứ hai gọi hook A rồi if(false) hook B, linked list bị lệch → state sai → crash.
2. **Chỉ gọi hooks trong React function component** — không trong function JavaScript thường. Lý do: cần fiber node context để gắn linked list.

## 10. Recap

1. **Hooks** là hệ thống cho phép function component kết nối vào React internal state + lifecycle. React lưu hooks dưới dạng **linked list gắn trên fiber node**.
2. **Rules of hooks** tồn tại vì React dùng thứ tự gọi hooks để ghép state — không đặt trong if / fo r /function lồng.
3. **useState** quản lý dữ liệu thay đổi, trigger re-render. Dùng functional update khi setState dựa trên giá trị trước.
4. **useEffect** quản lý side-effect gắn với lifecycle. Luôn xác định dependency rõ ràng. Return cleanup function khi cần.
5. **useRef** truy cập DOM element và giữ giá trị ổn định qua render (không gây re-render).
6. **useMemo** memoize kết quả tính toán đắt. Chỉ dùng khi compute function thực sự nặng.
7. **useCallback** memoize function reference. Cần thiết khi truyền function xuống child component dùng React.memo.
8. **Không dùng useEffect để derive data** — tính trực tiếp trong render hoặc dùng useMemo.
## 11. Góc nhìn nâng cao

Hooks thay đổi cách React nghĩ về lifecycle. Thay vì "component mounted → component updated → component will unmount", hooks nói: **"state A thay đổi, chạy effect X"**. Mental model chuyển từ **thời** **gian** (time-based) sang **dependency** (state-based).

Khi bạn nắm vững mental model này, các concept nâng cao như:

**Custom hooks** — gom logic theo tính năng, tái sử dụng

**useReducer** — state phức tạp có nhiều action **useLayoutEffect** — effect chạy đồng bộ sau DOM mutation, trước paint

...trở nên tự nhiên vì chúng chỉ là mở rộng của cùng một nguyên lý: state thay đổi → dependency thay đổi → hook chạy lại.

***P13 — The one thing most people get wrong:** Hooks KHÔNG phải "lifecycle method trong* *function component". useEffect KHÔNG phải componentDidMount + componentDidUpdate +* *componentWillUnmount gộp lại. useEffect là **cơ chế đồng bộ hóa** (synchronization* *mechanism): bạn khai báo "state X cần được đồng bộ với world bên ngoài", React đảm bảo effect* *chạy đúng lúc. Nghĩ về synchronization, không phải lifecycle.*

### P12 — Hooks behavior không hiển nhiên

**useState không merge object** như this.setState trong class component — phải tự spread. **useEffect không chạy đồng bộ** — nó chạy sau khi browser paint, khác với useLayoutEffect chạy trước paint. **useMemo không đảm bảo không tính lại** — React có thể flush cache để giải phóng memory. Không dùng useMemo cho side-effect. **useRef không thông báo khi.current thay đổi** — set.current không trigger re-render. **Rules of hooks không enforced bởi JavaScript** — bởi ESLint plugin ( eslint-plugin-react-h ooks ). Nếu không có ESLint, vi phạm rules không gây lỗi syntax, chỉ gây bug runtime khó tìm.
